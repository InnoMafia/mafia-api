# Работа с mafia-api

- Здесь находятся правила, проверка прав, хранение данных и контракт Protobuf.
  Веб-интерфейс живёт в `mafia-web`, общая среда запуска — в `mafia-ops`.
- Следуйте [архитектуре](docs/architecture.md). Для игровых сценариев используйте
  `mafia-old` как справочник поведения. Реализацию проектируйте для Go и PostgreSQL.
- Все обращения к ресурсам клуба проверяют членство и право на операцию.
  Добавляйте проверки для нескольких клубов, когда появляется новый маршрут.
- При реализации создания игры проверьте, что API разрешает его судье целевого
  клуба и отклоняет запрос обычного участника, владельца без роли судьи и
  пользователя, у которого эта роль есть только в другом клубе.
- Обработчики в `internal/handler` преобразуют запросы и ответы транспорта.
  Правила и контракты доступа к данным находятся в `internal/usecase`,
  реализации для PostgreSQL — в `internal/repository`. Для каждой сущности
  используйте отдельный Go-файл внутри пакета репозиториев. Собирайте зависимости
  в `cmd/api`.
- Для каждого сервиса используйте один `.proto` в `api/`. В нём объявляйте
  RPC, их запросы, ответы и HTTP-привязки `google.api.http`.
- Храните результаты Buf в `gen/` и обновляйте их через `make generate`.
  Для каждого RPC используйте отдельный Go-файл в слое обработчиков.
  Заготовки, которые дописывает разработчик, тоже относятся к исходному
  коду своего слоя. Перед коммитом запускайте `make check`.
- Для тестов и логов используйте синтетические данные. Секреты остаются
  в окружении, ошибки подключения не печатают строку PostgreSQL.
